## TL;DR

Every child ticket currently passes six stacked check events between "implementation complete" and "merged," and roughly half of that coverage is duplicate: two full-checklist review loops (two fable finals) over substantially the same diff, a quality-gate phase whose child-level checks are restatements of its neighbors, an unconditional second run of every test suite, and an evidence-checker that re-verifies work the same session just executed. This release consolidates the delivery lane to one full review gate (pre-PR, unchanged) plus a delta-scoped integration pair at the child-PR seam, retires the quality-gate skill with every check re-homed by scope — including its one non-redundant piece, the epic-level horizontal pass, which becomes an integrated-head review round in `submit-epic-pr` — makes the second suite run conditional with a fail-closed ancestry predicate, scopes the evidence-checker to adoption boundaries with a compaction guard, and wires per-gate catch attribution across every reviewer so future tuning is empirical.

## Key Points

- **No fable gate is removed, and no material loses tier diversity.** Delivery-phase fable rounds stay at two — the pre-PR full gate (unchanged) and the child-PR final **re-aimed** from a duplicate full checklist to an integration/delta lens. The child-PR seam keeps an opus round too (delta-scoped): the tests are reviewed only there, verify-stage fix deltas there plus the pre-seam focused re-review, and the tier-diversity doctrine requires two failure-mode-diverse tiers on that seam material. The redundancy removed is the duplicated full checklist, not round count: happy-path reviewer dispatches are unchanged; their scope shrinks to the delta. Spec review, plan review, coherence review, and the Gate 1 package are untouched.
- **quality-gate is retired as a skill and as a child-lane phase.** Child-level checks land in existing gates by scope (coverage-conservation table below). Its **epic-level horizontal value is re-homed, not deleted**: `submit-epic-pr` replaces "run epic-level quality-gate" with an **integrated-head review round** (fresh `opus`, once per **epic-PR attempt**, **positioned before the full-regression gate**, looping with mechanical fixes until a fresh round is clean — the head is then frozen for the attempt, and any head movement restarts it) carrying **all six horizontal classes at cross-child scope** — implementation compliance **against Gate 1 as amended by the register canon**, security, hygiene, regression risk, docs coherence, operational interactions, plus contract seams between children — on the post-sync integrated diff, with the same admissibility sentence as the child-PR rounds. At the epic level the pass has no redundant neighbor, so it stays; only its skill wrapper goes.
- **The child lane loses one phase and one checkpoint** (`quality-gating`); the mandatory reset seam moves from quality-gate→PR to verify→PR.
- **Local CI at the child-PR stage becomes conditional** — valid because `verify` now dispatches the **local-CI runner itself** (the existing prompt, discovery mandate intact) alongside the per-group Contract runners, so the seam re-run adds nothing when the tree is unchanged. The predicate's inputs are **durable by construction**: the `ready-for-child-pr` checkpoint records each runner digest's head SHA (the local-CI runner's named explicitly), because the evaluator sits on the far side of the lane's mandatory reset — session-ephemeral digests could never reach it. Skip requires: no commits after the head SHA the checkpoint records for the **local-CI runner** specifically (absent ⇒ dispatch; a newer test-runner SHA never substitutes), **that SHA an ancestor of current HEAD** (any rebase/rewrite orphans it and forces dispatch), and no epic-branch sync (any sync forces dispatch). Rationale is latency, not cost — 0.14.1 lanes are serial, so unconditional double suite runs directly gate epic throughput.
- **Evidence-checker scopes to adoption:** dispatched when any Lane Checkpoint in the trail carries a foreign or missing session run id, **or when any own checkpoint predates the session's last compaction** (post-compaction knowledge is reconstructed, not observed — adopted; when in doubt, dispatch). `pickup-next` ticks always adopt. All four consumer texts restating the old unconditional rule are swept (`submit-ticket-pr` § Merge, drive-epic, state-transitions, pickup-next ×2).
- **Verify-stage product fixes get an explicit backstop:** the focused re-review rule is pinned (fresh opus reviewer, fix delta + blast surface, before the seam) and fix deltas are a named child-PR integration aim.
- **Catch-attribution rider, fully wired:** every reviewer prompt (spec, plan, pre-PR, child-PR integration, epic integration, coherence) emits `caught-by: <gate>/<round>/<tier>` per finding; verify/local-CI failures are tagged by the dispatcher. Per-gate catch rates become grep-aggregatable — the data this consolidation currently lacks; DOD-650 is the first measured sample.
- **Merge eligibility gets one source of truth** (`submit-ticket-pr` § Merge). The 0.14.2 doctrine invariant holds on every path: the final gate before merge is fable, and the writer is never fable.
- **Out of scope:** the execution-model flatten (nested-dispatch redesign) moves to 0.16.0; parallel lanes, pickup-next deletion (0.14.1 live-test gate item), and the Frontier-findings flywheel are unchanged.

## Why (census)

Happy-path checks per child ticket today: spec review (fable loop), plan review (fable loop), per-task self-review, **pre-PR review (opus ≤5 + fable final)**, verify (haiku runners), **quality-gate (sonnet, 7 checks)**, **child-PR review (opus ≤5 + fable final, full checklist again)**, **local CI (re-runs the same groups)**, **evidence-checker**, verify-merge/cleanup scripts, coherence review (fable). The five bolded events all inspect substantially the same child diff for substantially the same properties. Field evidence attributes recorded catches to the maturity gates (DOD-727 plan review: 4 majors), the fable rounds on invariant-dense work (DOD-767/768), and the coherence design — none to the second full-checklist pass, the child-level quality-gate phase, or the duplicate suite run, though attribution has not been recorded systematically (hence the rider).

## Change 1 — Child-PR review re-aims to a delta-scoped integration pair

**Pre-PR context: unchanged.** The full gate stays where a catch is cheapest (before test investment): fresh-context opus rounds (cap 5) + fable final round, full checklist, in `deliver-ticket` step 3.

**Verify-stage fixes (the window between the full gate and the seam):** when a verification failure is classified an implementation bug and a fix worker changes product code, the focused re-review rule applies **as an explicit lane step, tier-pinned**: a fresh `opus` reviewer reads the fix delta plus its blast surface (callers/consumers), full checklist scoped to that delta, before the reset seam. (The rule exists today in `review` § Epic Lane Rules with no tier or scope pinned; this release pins it in place — it remains the only focused-re-review text.)

**Child-PR context: one opus integration round + one fable integration final** replace the second full loop. Both rounds carry the same delta/integration aim — exactly what is new or changed since the full gate:

- the tests (they did not exist at the pre-PR gate) — quality (vacuous asserts, mocked-out units under test, wrong-branch coverage) and coverage against the Testing Contract
- implementation deltas since the pre-PR gate (verify-stage fixes), re-checked in place
- the epic-branch delta: interactions with anything merged into the epic since the plan/branch point; branch currency
- unintended behavior changes relative to the ticket scope (requires reading the whole PR diff)
- docs and operational follow-through where behavior shifted after the pre-PR gate
- PR body/evidence sanity

The rounds read the whole PR diff (they must, for the unintended-changes check). **Aim guides attention, not admissibility: any defect seen anywhere in the diff is a legal finding** — the rounds simply do not re-execute the generic checklist the pre-PR gate owns. Findings route to fix workers (`sonnet`; `opus` on `needs-capable-delivery`) followed by a focused fable re-round; total child-PR rounds cap at 5 as today, **cap semantics unchanged: cap exhaustion escalates with unresolved findings, it never merges**, and the gate is clean only when a fable round reports zero issues. (The pre-seam focused re-review uses the same loop semantics — findings → fix worker → fresh focused round — under the pre-PR loop's own cap; a scoped instance of the existing fix loop, not new machinery.) Conditional local CI (Change 3) dispatches in parallel with the opus round when it runs at all.

**Tier-diversity conservation:** the seam-only material (tests, fix deltas, sync) sees both a Capable and a Frontier pass — the same two-tier diversity the old full loop provided — while the already-gated implementation is not full-checklist-reviewed a second time. Happy-path reviewer dispatches per ticket are unchanged (2 pre-PR + 2 child-PR); their scope shrinks.

**Prompt split:** `review/review-prompt.md` keeps the full checklist for post-implementation and pre-PR contexts and drops its "child-PR additional checks" section; a new `review/child-pr-integration-prompt.md` carries the integration aim with per-round model pins (`opus` round, `fable` final), the admissibility sentence, the leaf rule, and the `caught-by` output tag (Change 5). No repo-only file references (decree 5). Added to `validate-phase-skills.sh`'s prompt list.

**Decree compliance:** delivery-phase fable rounds remain two, now with diverse aims — full-gate (complete pre-PR implementation) and integration (tests + delta + seam) — and the coherence review remains the third fable pass with the alignment aim. Nothing is removed; the duplicate aim is re-pointed at the material the pipeline previously never fable-reviewed. On every path (happy, fix-loop, cap-exhaustion escalation, focused re-round) the last gate before merge is fable and the writer is never fable.

## Change 3 — Conditional local CI at the child-PR stage

- **Coverage-equivalence precondition (why the skip is valid):** after Change 2, the verify stage ran the *same* local-CI runner prompt (discovery mandate intact) plus the per-group Contract runners. The seam re-run adds nothing when the tree hasn't changed — equivalence holds by prompt identity, not by scope paraphrase.
- `verify/test-runner-prompt.md` **and** `submit-ticket-pr/local-ci-runner-prompt.md`: digests additionally record the **head SHA** the commands ran against. The local-CI runner prompt also gains the optional `groups-covered-elsewhere` scope input (verify-stage dispatches pass it; child-PR re-dispatches run un-scoped, as today).
- `review` (child-PR context): the evaluator reads the predicate's inputs **from the `ready-for-child-pr` checkpoint** (the durable home of the recorded head SHAs — the evaluator runs on the far side of the lane's mandatory reset, so session-ephemeral digests cannot reach it). The local CI dispatch is **skipped** iff **(a)** no commits exist on the child branch after the head SHA the checkpoint records for the **local-CI runner** — that runner specifically, never a newer test-runner SHA (a verify-stage fix re-runs affected groups but not necessarily the local-CI runner, so keying on "newest digest of any kind" would certify local-CI coverage at a SHA it never ran against); no recorded local-CI SHA ⇒ dispatch — **(b)** that recorded SHA **is an ancestor of the current child HEAD** (`git merge-base --is-ancestor`; a rebase-style rewrite orphans it — predicate fails, dispatch forced), and **(c)** the epic branch has not moved: **any epic-branch sync (merge or rebase) forces the dispatch** — the sync-then-rerun rule explicitly includes the CI runner. Otherwise dispatch as today. The predicate fails closed: not decidable ⇒ dispatch. The unconditional full regression on the integrated epic head before the epic PR is unchanged (different integration state — justified).
- `submit-ticket-pr` § Merge evidence: "local CI-equivalent command evidence" is satisfied by the **checkpoint-recorded** verify-stage digests under the same predicate (the durable record, not session memory).

## Change 4 — Evidence-checker scopes to adoption boundaries

New rule, stated once in `epic-orchestrator` § Merging / § Evidence Rule (single source; consumers reference it): the merge slot dispatches the evidence-checker **iff it is adopting work it did not execute and directly observe** — concretely, when any Lane Checkpoint in the trail carries a foreign or missing session run id, **or** any own-run-id checkpoint predates the session's last compaction (a deliberate compaction is a voluntary crash + resume: post-compaction knowledge of prior steps is reconstructed from durable state, not observed, so those checkpoints are adopted). When every checkpoint was written by this session in its current context window, the checker is skipped: results were claimed only from leaf digests as the lane was walked, and the merge retains its script-owned postcondition (`verify-merge.sh`) and branch-currency check. **When in doubt, dispatch — the predicate fails closed.** (Scope: this rule governs the merge-slot adoption gate only; the janitor's read-only reconciliation checkers in `reconcile-tickets` are a different context and are untouched. Non-merge state advances follow the same adoption test — own-session in-context work advances on its leaf digests; adopted work takes the checker — which is the reading `pickup-next`'s scoped line 54 states.)

Consumer texts swept to match (they currently restate the unconditional rule):

- **`submit-ticket-pr/SKILL.md` § Merge step 1** (line 34, "…verified by an evidence checker") — the designated single source of merge eligibility must itself state the conditional: "evidence-checker citations when adopting (per the epic-orchestrator Evidence Rule); own-session evidence trail otherwise".
- `epic-orchestrator/state-transitions.md` `ready-to-merge-child` row (Child-Ticket table), Required-evidence cell → "own-session evidence trail (all checkpoints this run id, written this context window) or evidence-checker citations (adoption); child branch current with epic head".
- `pickup-next/SKILL.md` line 54's absolute → scoped phrasing, **and line 30's "evidence-checker verification … before merging" gains the one-clause note "(a tick is always an adopting session, so this always fires)"** — tick behavior is unchanged.
- `drive-epic/SKILL.md` contract-row delegation cell notes the checker is conditional per the epic-orchestrator rule (the driver's inline-walked lanes are the primary skip case).

## Change 5 — Catch-attribution rider (fully wired)

Every posted review-evidence finding (lane checkpoint evidence, review comments, escalations, demotion comments) carries `caught-by: <gate>/<round>/<tier>` — gate ∈ {spec-review, plan-review, pre-pr, focused-re-review, verify, local-ci, child-pr, epic-integration, coherence}. **Emitters cover the whole enum:** the per-finding tag is added to the output format of `review-prompt.md`, `child-pr-integration-prompt.md`, `brainstorm/spec-reviewer-prompt.md`, `write-plan/plan-reviewer-prompt.md`, `epic-orchestrator/coherence-reviewer-prompt.md`, and the new `epic-integration-reviewer-prompt.md` (one output-format line each); `verify`/local-CI **failures** are tagged by the dispatcher in the next boundary's checkpoint evidence (`ready-for-child-pr`) (runners stay pure). **Gate-token composition:** single-gate prompts hard-code their token; `review-prompt.md` serves two epic-lane gates (`pre-pr`, `focused-re-review`) plus the interactive post-implementation context, so for that prompt the **dispatcher supplies the `<gate>` token** from the invoking context (interactive post-implementation runs carry `pre-pr`-equivalent attribution or none). Round and tier are appended by the dispatcher when posting. **Round grammar (pinned so DOD-650 data composes):** `<round>` is an integer counting rounds within that gate's loop for this ticket; a fable final is its integer (not "final"); single-shot gates (verify, local-ci, coherence) use `1` per attempt; `epic-integration` counts rounds within its per-attempt loop like the review gates (its v6 lifecycle is a loop, not a single shot). **Tagging surfaces (append-only — never edit a posted checkpoint):** tags land in the **next boundary's evidence** — verify-stage failures in the `ready-for-child-pr` checkpoint evidence; a child-PR-stage local-CI failure (when the conditional dispatches it) in the lane's `ready-to-merge-child` exit report. No new artifact, no script: the tag is grep-aggregatable from PM comments; DOD-650 is the first measured sample, and the triple-fable coverage-diversity check already on the watch list becomes a data read.
