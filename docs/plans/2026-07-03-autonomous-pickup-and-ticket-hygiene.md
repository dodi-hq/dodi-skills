# Autonomous Pickup & Ticket Hygiene Implementation Plan

> **For agentic workers:** Execute tasks in order. Single tree — all skill edits under `dodi-dev/skills/`.

**Goal:** Ship the 0.12.0 workflow: a stateless `pickup-next` tick that runs as a native scheduled task and advances one ticket per run, a `reconcile-tickets` janitor that closes the merge→deploy status loop against GitHub, and the PR↔ticket linking convention that lets Linear's GitHub integration do the event-side work.

**Spec:** `docs/specs/2026-07-02-autonomous-pickup-and-ticket-hygiene-design.md`

**Testing Contract (repo-native):** the three validation scripts are the regression suite — `scripts/validate-plugin-metadata.sh`, `scripts/validate-phase-skills.sh`, `scripts/validate-ticket-comment-templates.sh` — all must exit 0 after every task. No code harness applies to a markdown policy package.

## Tasks

1. **New skill `pickup-next`** (`dodi-dev/skills/pickup-next/SKILL.md`, `model: sonnet`): the scheduled tick. Contract; scope restricted to epics carrying `epic-signed-off` (pre-Gate-1 work stays interactive); one action per run selected by priority (merge ready child → submit epic PR → resume RESUMABLE lane → dispatch deliver-ticket → mature-ticket); claim comment (host, timestamp, action, attempt counter) posted before acting, updated with the exit state after; live-claim skip; retry ceiling of 3 consecutive failed/RESUMABLE attempts → `blocked` + escalation comment; silent no-op exit when nothing is actionable. Routes via `epic-orchestrator/state-transitions.md` and reuses its state-reader and evidence-checker prompts (in-plugin references). Includes a Scheduled Task Setup section: desktop scheduled task, ~15-minute off-peak cron, Auto permission mode, worktree-per-run, no-overlap semantics; Cloud Routine noted as the machine-off upgrade path (harness-neutral phrasing per AGENTS.md).
2. **New skill `reconcile-tickets`** (`dodi-dev/skills/reconcile-tickets/SKILL.md`, `model: sonnet`): the convergence janitor. Contract; one sweep per run over the spec's drift table (merged/closed child PRs, Gate 2 epic merge → Merged for epic + children, production deploy success → Deployed/Released + branch/worktree cleanup, claim leases older than 2h, retry-ceiling `blocked` clears when the blocker demonstrably resolved, ambiguity → escalation comment — never guess). Deploy signal: GitHub deployment status via `gh api` (deployments + statuses; success on a SHA that reaches the merged epic commit). Destructive limits: delete only branches verified merged by SHA reachability from main/master; repairs state, never dispatches work. Scheduled Task Setup section: once daily after the nightly deploy window; raise cadence only if the Linear GitHub integration is absent.
3. **Demote `epic-orchestrator`** (`epic-orchestrator/SKILL.md`): reframe from resident supervisor to (a) the interactive entry point for epic intake through Gate 1 (pickup-epic, assess-epic, Gate 1 package/signoff) and (b) the home of the shared routing contract (state tables, state-reader/evidence-checker/gate1-package prompts) that `pickup-next` consumes. Post-Gate-1 advancement is normally tick-driven; a manually run orchestrator session remains valid and uses the same claim discipline so ticks and manual runs don't collide. Description and Allowed Next Actions updated accordingly; no long-lived loop.
4. **PR↔ticket linking convention** (`pickup-ticket/SKILL.md`, `submit-ticket-pr/SKILL.md`, `submit-epic-pr/SKILL.md`): child branches named `<user>/<ticket-id>-<slug>` (Linear's branch-name format, lowercase ticket id per Linear convention); child PR bodies carry a non-closing `Part of <ticket-id>` reference (children close on epic merge, not child merge); the epic PR body carries `Closes <epic-id>` plus the child ticket list.
5. **Templates** (`templates/ticket-comments/`): new `claim.md` (Claim / Attempt / Exit sections) and `deploy-confirmation.md` (Deployment / Tickets Updated / Cleanup sections); both wired into `validate-ticket-comment-templates.sh`.
6. **AGENTS.md**: new Scheduled Operation section — ticks are stateless (fresh session per run, PM is the only state), one action per run, claim + retry-ceiling discipline, janitor repairs but never advances work, scheduling is harness-native (never hand-rolled cron/daemons); Gate 2 remains procedural (no scheduled run ever merges an epic PR).
7. **Validators**: `validate-phase-skills.sh` gains `pickup-next` and `reconcile-tickets`.
8. **Metadata bump** to `0.12.0` (three files) + full validation run + local plugin update.
